# チケット 29: 排気量の設定契約と回転モデルへの反映

## 目標

総排気量をモデル入力として導入し、同じ基準エンジンの排気量変更が駆動トルクへ反映されるようにする。既存トルク曲線の意味を明示し、排気量による二重補正を防ぐ。

## 調査根拠

`src/engine/config.ts` のEngineConfigには排気量がなく、未知のキーを拒否する。`src/engine/dynamics.ts` はトルク曲線を補間し、開度とlimiter倍率を掛け、慣性で割って回転を更新する。`src/presets/*.ts` は曲線と慣性を直接指定する。Workletでも構成を再検証するため、型の追加だけでは統合できない。

## 範囲 / 非対象

- 範囲: 総排気量・曲線の基準排気量、検証・clone/parse・プリセット・回転モデル・Workletの設定境界、互換性テスト。
- 非対象: UIの排気量編集と音色反映（チケット30）、ボア/ストローク・圧縮比・熱力学・実車性能の再現、drivetrainモデルの刷新。

## 実装契約と想定ファイル

- `src/engine/config.ts`、`src/engine/dynamics.ts`、`src/presets/*.ts`、`src/audio/worklets/`、関連controllerと`tests/engine/`・`tests/audio/`を対象とする。
- 総排気量`displacementCc`と曲線の基準総排気量`referenceDisplacementCc`を定義する。全気筒は等排気量とし、1気筒排気量は総排気量/気筒数から導出する。二重保存しない。
- 両値は有限の正数とし、実装時に用途に合う上下限と補正倍率の上限を決定し、理由を計画・validator・境界テストに一致させる。不正値を黙ってclampしない。
- 曲線は基準排気量での絶対トルク[N·m]と定義し、駆動トルクに`displacementCc / referenceDisplacementCc`を一度だけ掛ける。cycleDegreesによる追加の2倍補正はしない。曲線自身が基準エンジンのサイクル特性を表す。
- 慣性、摩擦、idle補助、吸排気形状は今回自動スケールせず独立設定とする。この近似と、全回転域で実車性能を保証しないことを文書化する。
- 既存schemaVersion 1で両値を欠く構成は互換入力として受け入れ、1気筒あたりの明示した固定モデル値から両値を同じ値へ補完する。片方だけ欠く入力は拒否する。正規化済み内部snapshotでは両値を必須とし、UIとWorkletで同じ正規化を用いる。schema変更が必要なら同等の明示的な旧入力migrationを設ける。
- 全プリセットに実測ではないモデル排気量と同じ基準排気量を明記し、初期補正倍率は1とする。既存の曲線を暗黙に書き換えない。停止中の安全な構成適用と最後の正常snapshot維持を守る。

## 受け入れ基準

- 排気量未指定の旧構成と倍率1の新構成で、従来の回転応答が許容誤差内で一致する。
- 同一RPM・開度・曲線・慣性でlimiter/idle補助の影響を除いた条件では、排気量比に従って駆動トルクが変わる。正味加速度全体が単純比例するという誤った期待値は用いない。
- NaN、Infinity、0、負値、境界外、片方欠落をUI/Worklet境界で拒否し、clone後も両値が保たれる。
- 2/4ストローク、1/2/4/6/8気筒、複数バンク、neutral/gear/clutch、idle/limiter、対応範囲の上下限で有限かつ既存の回転・イベント上限内に収まる。
