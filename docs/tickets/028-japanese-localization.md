# チケット 28: i18n基盤と日本語・英語の表示切替

## 目標

日本語で全操作を理解でき、英語にも切り替えられるUIにする。翻訳を表示層へ集約し、エンジン/DSPの契約を言語から独立させる。

## 調査根拠

`src/app/App.tsx`、`src/components/EngineVisualizations.tsx`、`src/presets/*.ts` に表示文言があり、`src/engine/config.ts` の検証issueはpathと英語messageを返す。位相fieldsetの日本語と、それ以外の英語が混在しており、既存E2Eも英語のaccessible nameを多く参照する。単純なJSX置換だけではプリセット説明やエラーが英語のまま残る。`package.json` にi18n用依存はない。

## 範囲 / 非対象

- 範囲: ja/en辞書、言語選択と保存、可視ラベル・補助説明・エラー・ARIA・可視化・プリセット表示の翻訳、HTML言語属性。
- 非対象: リポジトリ文書の翻訳、3言語目、configのID・JSONキー・Workletプロトコルの翻訳。

## 実装契約と想定ファイル

- `src/i18n/` 等に型付きの翻訳キーと辞書、補間・数値表示を集約する。採用方式と依存追加の要否を実装報告に記録する。
- 初期言語は保存済みja/en → ブラウザ優先言語（ja系ならja）→ enの順で決める。画面から日本語/Englishを選べ、保存不可でも切替が動く。切替時に`document.documentElement.lang`とページタイトルを更新する。
- 表示本文、開始/停止や保留状態、構成エラー、音声利用不可/中断/失敗時の案内、可視化の説明・凡例、accessible name、プリセット名・説明を対象とする。RPM、FFT、単位や識別子など翻訳しない語を明記する。
- coreのエラーは安定したcode/paramsを表示層で翻訳する方式などを採り、英語messageの部分一致に依存しない。未知の実行時エラーには翻訳済み一般案内を出し、技術詳細は診断情報として区別する。core/WorkletにReactや辞書を持ち込まない。
- 数値表示はlocaleを考慮し、入力値・設定・通信は数値型と既存の単位契約を維持する。名前の翻訳でpreset IDやテスト用の安定した識別子を変更しない。
- 再生中や編集中の言語変更で、AudioContext、RPM、アクセル、ギア、適用済み/編集中/適用待ち構成をリセットしない。

## 受け入れ基準

- ja/enでキーの欠落と補間引数の不整合を検出し、キー文字列そのものやundefinedがUIへ露出しない。
- jaブラウザ初回、en fallback、保存した選択の再読込、保存拒否を検証する。
- 両言語で開始/停止・プリセット・無効な位相のエラー・設定適用・言語切替中の状態維持をE2Eで確認する。
- チケット27のPC/狭幅条件を両言語で満たす。日本語のARIA名、lang属性、グラフ表示も確認する。
