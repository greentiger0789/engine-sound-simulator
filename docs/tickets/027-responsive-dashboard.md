# チケット 27: レスポンシブ対応とPC向け横長ダッシュボード

## 目標

PCでは主要操作と可視化を同時に見渡せ、スマートフォンでは横スクロールせず操作できるレイアウトにする。レスポンシブ対応と横長化を一体として扱う。

## 調査根拠

`src/app/App.tsx` に運転操作・構成編集・可視化が集まり、`src/styles/index.css` と `src/components/EngineVisualizations.tsx` が配置と描画を担う。`.controller-area` は最大42remで中央に置かれ、`.app-shell` は単列のgridである。グラフ内の2列配置と34rem以下の切替はあるが、画面全体を横に活用できていない。既存E2Eの320px検証は主に燃焼マーカーの重なりが対象で、画面全体のoverflowやPCの配置は保証しない。既存のギア・クラッチ操作も配置対象に含める。

## 範囲 / 非対象

- 範囲: ページ全体の配置、必要な表示コンポーネント分割、可視化のサイズ追従、キーボード・タッチ操作、画面幅別E2E。
- 非対象: 音の変更、操作機能の削除、スマートフォン実機での音声動作保証。

## 実装契約と想定ファイル

- `src/app/App.tsx`、`src/styles/index.css`、`src/components/EngineVisualizations.tsx` と関連コンポーネント、`tests/e2e/worklet.spec.ts` または新規レイアウトspecを対象とする。
- 広い画面は操作・状態と可視化を複数列に配置する。構成編集と長い説明は明示的に開閉できる詳細領域へまとめ、初期状態で閉じる。詳細を隠しても適用待ち・検証エラーの存在と編集への入口は分かること。
- 1366×768および1440×900のCSS viewport、標準倍率、詳細を閉じた初期画面で、開始/停止・音量・RPM・アクセル・負荷・ギア/クラッチ・車速・プリセット選択・燃焼列・波形・FFTがページの縦スクロールなしで見えることを設計目標かつ自動受け入れ条件とする。文字やグラフを読めない大きさへ縮小して達成しない。
- 320、375、768px幅では内容に応じて列を減らし、ページの縦スクロールを許容する。設定表を含めページ全体の横スクロール、重なり、入力の欠落を防ぐ。詳細を開いた場合や200%ズームでは全内容へスクロールで到達できる。
- DOMの読み順とフォーカス順を自然に保ち、開閉ボタンの状態を支援技術へ伝える。画面幅変更や詳細開閉でAudioContext、入力値、適用済み構成を作り直さない。
- canvas/SVGはコンテナーの幅と画素密度へ追従し、非表示・再表示で描画やRAFを重複させない。タッチでアクセルを押したまま領域外へ移動した場合も解除できる。

## 受け入れ基準

- 上記PC viewportで主要領域の可視性をbounding box等で自動確認する。狭幅では詳細を開いた状態も含め横overflowがなく、8気筒設定を編集・適用できる。
- 開始/停止、プリセット適用待ち、アクセル解放、キーボード変速、可視化の既存回帰を維持する。
- サイズ変更前後で再生状態と入力値が維持される。200%ズーム相当の狭いCSS viewportでも操作へ到達できる。
- 代表的なPC/スマートフォン幅のスクリーンショットを報告へ添付し、文字とグラフの可読性をレビューする。
