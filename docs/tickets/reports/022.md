## Acceptance evidence

- `tests/engine/phase-events.test.ts` checks a single cylinder at 6000 rpm and
  44.1/48 kHz emits 100 events/s for a 360-degree cycle and 50 events/s for a
  720-degree cycle. It also checks three consecutive 360-degree crossings by
  exact cycle index and frame so the boundary is neither omitted nor doubled.
  The allocation-free `advanceRealtime` path used by the product Worklet checks
  the same rate matrix and boundary across irregular 128/64/256/127-frame
  partitions, including checked-path phase and frame parity.
- `tests/engine/config.test.ts` parses the new two-stroke preset and rejects a
  firing angle equal to its 360-degree cycle boundary.
  `tests/engine/multicylinder-presets.test.ts` continues to parse and exercise
  every existing 720-degree preset.
- `tests/audio/dsp.test.ts` checks that both 360- and 720-degree event streams
  trigger exactly one analytic DSP pulse per event, including the observable
  missing-event case.
- `tests/audio/controller.test.ts` checks stopped staging for valid 360- and
  720-degree snapshots and rejection at each active cycle boundary.
- `tests/audio/visualization.test.ts` checks that 180 degrees maps to 50% of a
  360-degree strip and that the 360-degree endpoint is excluded.
- `tests/e2e/worklet.spec.ts` selects the two-stroke preset in the product UI,
  observes the 360-degree label and bound, rejects 360 degrees, applies 0
  degrees while stopped, starts the real product Worklet path, observes the
  active 360-degree firing strip, and stops. The scenario passed in the Vite
  and Nginx projects during focused verification.
- The optional manual display/listening check was not performed. It is not a
  dependency-release condition for this ticket.
