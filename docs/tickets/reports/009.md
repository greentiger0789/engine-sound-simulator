## Acceptance evidence

- `tests/audio/engine-audio-processor.test.ts` initializes the production
  processor path at 44.1 and 48 kHz, renders uneven block sizes, and asserts
  finite protected output. Its throttle cases distinguish scalar and a-rate
  inputs and prove a mid-block opening is neither treated as fully closed nor
  retroactively applied to the full block.
- The processor trajectory case drives the integrated model open for two
  seconds, observes RPM rise by more than 500 rpm and effective throttle above
  0.99, then closes it for eight seconds and observes the configured idle band
  and a decayed intake state. The same case bounds telemetry to 20–30 Hz.
- The limiter integration case uses one processor runtime state for the
  dynamics drive multiplier and event mask. It observes torque multiplier zero
  with no new DSP triggers during cut, followed by hysteretic restart with
  multiplier one and resumed triggers. `tests/engine/dynamics.test.ts` separately
  verifies the multiplier bounds and the documented policy that idle assist is
  retained while combustion drive is cut.
- Processor initialization tests require a valid versioned `EngineConfig`
  snapshot before `config-applied` and same-request `ready`; invalid snapshots
  produce only `config-rejected` and silence. Fault injection verifies a
  non-finite AudioParam latches silence and emits `fatal-error`.
- `tests/audio/controller.test.ts` verifies that the controller remains muted
  and `starting` until ordered, matching `config-applied` then `ready` replies,
  ignores stale request/node replies, maps rejection and processor failures to
  UI errors, preserves the valid preset for retry, and sends throttle through
  the AudioParam boundary.
- `tests/e2e/worklet.spec.ts` exercises the actual emitted Worklet through the
  product UI in Vite and Nginx projects: user start, configuration readiness,
  nonzero RPM telemetry, throttle, volume/mute, stop, graph recreation, and
  typed load/processor error recovery.

## Review

- Self-review covered the complete `origin/main` working diff, including audio
  time ordering, scalar/a-rate sampling, limiter threshold timing, initialization
  handshake, stale messages, fault silence, telemetry cadence, UI state, and
  documentation. It strengthened the original mid-block test so a whole-block
  last-value implementation cannot pass, added an integrated open/idle return
  trajectory and telemetry-rate bound, and corrected test typing/lint issues.
- Two bounded Terra medium `ticket-worker` agents implemented non-overlapping
  processor/core and controller/UI/E2E paths. The orchestrator retained shared
  contracts, integration, documentation, Git, and delivery ownership.
- A fresh Terra high `ticket-reviewer` found two substantive issues: the first
  processor path allocated array views, event objects, phase copies, and an
  input object on each audio block; and telemetry could drop below 20 Hz for an
  accepted 4,096-frame block. The correction added caller-owned typed event and
  signal storage with allocation-free realtime dynamics/phase/event/DSP APIs,
  and moved telemetry emission to carried audio-frame boundaries inside each
  block. New 44.1/48 kHz tests use uneven 2,048/4,096-frame blocks, assert the
  allocating fallback APIs are unused, and observe exact 30 Hz frame cadence.
- Recheck found one defensive numerical boundary in the realtime dynamics API:
  an extremely small positive sample rate could make the per-frame duration
  infinite. The correction validates derived and accumulated elapsed time and
  retains the existing ten-second per-call bound; direct regressions cover both
  overflow and oversized duration. The reviewer confirmed all findings resolved
  without new timing, limiter, lifecycle, or realtime-allocation regressions.
  No actionable findings remain.
