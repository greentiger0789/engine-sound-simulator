## Accepted scope and rationale

- The current `typescript-eslint` release available from npm still declares its
  peer range as `>=4.8.4 <6.1.0`, so the repo intentionally did not force a
  TypeScript 7 upgrade through `--force` or a peer-warning bypass. The project is
  therefore upgraded to Node 26 LTS while remaining on the officially supported
  TypeScript/lint path available in this environment.
- The migration target is the actual Node 26 runtime contract: Docker base image,
  `engines.node`, `@types/node`, lockfile generation, and the developer docs that
  describe the supported runtime.

## Acceptance evidence

- Node.js gate — met. The official Node.js release schedule has Node.js 26
  available as LTS and the repository now pins `node:26.12.0-bookworm-slim`.
- Package metadata — aligned. `package.json` now requires
  `node >=26.12.0 <27` and `@types/node` is updated to `26.6.6`.
- Docker verification — successful. The project’s tooling image was rebuilt and
  the repo was installed under the Node 26 runtime with `npm install` in the
  official `node:26.12.0-bookworm-slim` image.
- Lockfile — regenerated under Node 26 and recorded in the repo.
- Documentation — updated to the Node 26 LTS contract in README and the
  implementation plan.

## Review

- Confirmed that the migration only changed runtime/tooling metadata and
  documentation, without altering app logic or DSP behavior.
- The update intentionally keeps the repo on the officially supported
  TypeScript/lint combination instead of forcing a TypeScript 7 upgrade that is
  not yet supported by the current `typescript-eslint` peer range.

## Verification

- `docker run --rm -v "$PWD":/workspace -w /workspace node:26.12.0-bookworm-slim sh -lc 'npm install --no-audit --no-fund'`
  completed successfully after the metadata update.
- `docker run --rm node:26.12.0-bookworm-slim sh -lc 'node -v && npm -v && npm view typescript version && npm view @types/node version && npm view typescript-eslint version'`
  confirmed the target baseline: Node `v26.12.0`, npm `11.20.0`, TypeScript
  `7.0.2`, `@types/node` `26.6.6`, and the current stable `typescript-eslint`
  release available in the registry.
- This project keeps `typescript` on the supported `6.0.3` release because the
  currently published `typescript-eslint` peer range is still `>=4.8.4 <6.1.0`;
  the upgrade therefore remains on the stable compatibility path rather than a
  forced workaround.

## Limits and next actions

- If the lint toolchain later adds official TypeScript 7 support, the next step
  is to raise TypeScript and the matching ESLint stack together under a fresh
  migration ticket.
- The current change completes the Node 26 upgrade for this repository without
  bypassing upstream support guarantees.
