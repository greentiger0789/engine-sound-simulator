## Acceptance evidence

The pre-migration `npm run lint` passed in the Docker `tools` service. ESLint's
effective configuration was captured with `eslint --print-config` and contains
the following rule groups:

| Existing ESLint coverage                                                                                                                                                                                                                                     | Oxlint native mapping                        | Disposition                                                                                                         |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `@typescript-eslint` recommended rules (20 enabled rules, including `no-unused-vars` and `no-empty-object-type`)                                                                                                                                             | `typescript/*` equivalents                   | Stable native rules are available                                                                                   |
| `react-hooks/rules-of-hooks`                                                                                                                                                                                                                                 | `react/rules-of-hooks`                       | Stable native rule is available                                                                                     |
| `react-hooks/exhaustive-deps` (warning)                                                                                                                                                                                                                      | `react/exhaustive-deps`                      | Stable native rule is available                                                                                     |
| `react-hooks/static-components`, `use-memo`, `void-use-memo`, `preserve-manual-memoization`, `incompatible-library`, `immutability`, `globals`, `refs`, `set-state-in-effect`, `error-boundaries`, `purity`, `set-state-in-render`, and `unsupported-syntax` | Corresponding `react/*` React Compiler rules | Native implementations exist, but Oxlint documents the React Compiler rules as experimental and disabled by default |
| `react-hooks/config` and `react-hooks/gating`                                                                                                                                                                                                                | None                                         | Oxlint's official React Compiler mapping marks both rules as not implemented                                        |

An isolated Docker fixture using `oxlint@1.82.0` confirmed that native Oxlint
can report an unused type/variable, an empty object type, a conditional Hook, a
missing Hook dependency, and render-time `Math.random()` through
`react/purity`. The exact fixture was:

```tsx
import { useEffect, useState } from "react";

type EmptyObject = {};
const unusedValue = 1;

export function Fixture({ enabled }: { enabled: boolean }) {
  if (enabled) useState(0);
  useEffect(() => console.log(enabled), []);
  return <div>{Math.random()}</div>;
}
```

It was checked in the `node:24.21.0-bookworm-slim` image with:

```bash
npx -y oxlint@1.82.0 --react-plugin \
  -D no-unused-vars \
  -D typescript/no-empty-object-type \
  -D react/rules-of-hooks \
  -D react/exhaustive-deps \
  -D react/purity /tmp/fixture.tsx
```

The expected nonzero result contained six errors: unused `EmptyObject`, empty
object type syntax, unused `unusedValue`, conditional `useState`, missing
`enabled` dependency, and render-time `Math.random()`. This proves those rule
implementations are available, but it does not provide the two missing rules or
make the compiler-backed rules stable. Oxlint's
[built-in plugin documentation](https://oxc.rs/docs/guide/usage/linter/plugins)
identifies the compiler rules as experimental and off by default; its
[React Compiler mapping](https://oxc.rs/blog/2026-08-18-react-compiler-support)
marks `config` and `gating` as not implemented.

The remaining acceptance criteria cannot be satisfied together:

- Enabling the implemented compiler rules would not provide the ticket's
  required stable equivalents.
- `config` and `gating` cannot be mapped to native Oxlint rules at all.
- Omitting them would reduce the current `recommended-latest` diagnostics.
- Keeping ESLint avoids a regression but fails the required complete removal of
  ESLint dependencies and configuration.

No package, lockfile, lint script, formatter, CI, application, or DSP changes
were made. The existing browser/node targets, ignores, Prettier, Markdownlint,
and `Repository checks` gate remain unchanged.

## Limits and next actions

Ticket 25 remains blocked until Oxlint both implements `config` and `gating` and
provides stable equivalents for the required React Compiler rules, or the
ticket owner explicitly changes the contract to permit a hybrid ESLint path or
reduced/experimental compiler-rule coverage. The existing ESLint lint path
remains intact, so this branch does not weaken the repository gate. The optional
editor validation was not run.
