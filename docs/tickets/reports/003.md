## Acceptance evidence

- Unit tests verify that no `AudioContext` exists before `start()`, repeated
  starts share one graph, a suspended graph resumes in place, and a stop queued
  during module loading cannot connect a late node.
- Unit tests verify 30 ms gain ramps for start and stop, clamped volume, mute,
  teardown, and safe retry after a processor failure.
- Worklet tests at 44.1 and 48 kHz and frame lengths 1, 127, 129, and 257 verify
  a finite analytical signal below 0.06 peak, with scalar and per-frame gain.
  The controller additionally sets the processor gain to 0.15 before output.
- Typed snapshots distinguish insecure context, unsupported audio APIs, Worklet
  loading, processor, fatal processor-message, context-state, and start errors;
  the React alert renders their code and message.
- Playwright verifies the real product UI in Vite and Nginx modes: initial idle
  state with zero contexts, real Worklet start, volume, mute, stop, and a second
  complete start/stop with exactly one new node for that lifecycle.
- A module-scope controller outlives React StrictMode's development remount, so
  React subscriptions can remount without creating or connecting another node.

## Review

- Self-review covered `origin/main...975c89d`, including lifecycle concurrency,
  error cleanup and retry, output amplitude, AudioParam shapes, StrictMode
  ownership, accessible UI state, and development/production Worklet assets.
- Two Terra medium `ticket-worker` agents implemented the non-overlapping audio
  core and UI/E2E paths. The orchestrator owned contracts, integration, Git,
  documentation, and verification.
- Self-review corrected suspended-context reuse, stop-during-start serialization,
  failed-graph teardown before retry, typed error codes and missing error-path
  coverage. Integration also corrected the E2E web image to copy Worklet shared
  chunks after the product began importing its contract.
- The independent Terra high reviewer found two medium-severity issues: stopping
  during the initial ramp could seed the stop ramp from the target gain, and
  the product E2E treated local graph construction as success without awaiting
  the Worklet's `ready` message. The correction holds the calculated current
  envelope value (using `cancelAndHoldAtTime` when available), gates `running`
  on the active processor's handshake, and prevents a late message from
  reviving a stopped graph. Recheck found one further medium issue where a
  repeated start during ready-wait rebuilt the graph. The final correction makes
  pending starts idempotent and queues a restart requested during stop. Unit and
  product E2E checks passed after correction. The reviewer completed a clean
  final recheck with no remaining actionable findings.
