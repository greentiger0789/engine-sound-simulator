## Scope

- Ticket: [単気筒パルス DSP と出力保護](../008-single-cylinder-pulse-and-protection.md)
- Reviewed implementation commit: `1a90c5b`.
- Added a browser-independent, stateful single-cylinder DSP that turns existing
  `FiringEvent` values into analytic smooth pulses. Event offsets affect the
  first rendered sample, while pulse and DC-filter state continue across blocks.
- Load controls pulse amplitude and width. The final stage applies an 18 Hz DC
  blocker, a conservative `0.18` default gain, bounded soft limiting, exact
  mute, finite-value monitoring, and a latched transition to silence.
- Added constructor-preallocated pulse state with explicit active and per-block
  event bounds, trigger telemetry, reset support, and an offline helper that
  delegates each finite block to the production sample loop.

## Acceptance evidence

- `tests/audio/dsp.test.ts` renders idle, 50% load, full load, and an abrupt
  `0.05` to full-load transition for two seconds at both 44.1 and 48 kHz. Every
  output sample is finite; after the initial half-second, peak stays below 1,
  absolute DC stays below `0.003`, and RMS is nonzero.
- The same test constructs the existing ticket 7 `FiringEventGenerator` at
  6000 rpm over a 720-degree cycle. It produces 50 events in one second and the
  DSP trigger count is exactly 50; removing one event produces exactly 49.
- Exact Float32 waveform equality is checked for identical inputs and for
  partitions of 1, 128, and uneven `127, 128, 19, 301` frames. Different
  within-sample offsets produce different first-sample responses.
- An 11-second-plus-17-frame render at 44.1 kHz uses repeated
  `1, 127, 128, 509` frame blocks and retains finite pulse/filter state.
- Invalid load and an intentionally over-dense event block latch a named fault,
  clear bounded active state, zero the entire current block, and keep following
  blocks silent. Mute is asserted as exact zero output while state advances.
- A 256-event coincident block at unity test gain drives the limiter above `0.9`
  while remaining finite and at or below 1. Removing limiting would exceed the
  asserted peak. A separate test confirms higher load increases both pulse peak
  and its late tail.
- Oversized event input is rejected from its O(1) length before any indexed
  event access. Pulse ages, amplitudes, and widths use three fixed-capacity
  typed arrays allocated by the constructor, with no per-trigger object, array,
  or map allocation. Numerically unusable DC coefficients are rejected.
- A Docker offline measurement used 100 events over two seconds at 50 events/s,
  block sizes `127, 128, 31`, default protection, and the settled final 1.5
  seconds. Values were:

  | Sample rate | Condition | RMS      | DC          | Peak     |
  | ----------- | --------- | -------- | ----------- | -------- |
  | 44.1 kHz    | idle      | 0.000914 | -0.00000043 | 0.002293 |
  | 44.1 kHz    | mid       | 0.003951 | -0.00000206 | 0.006389 |
  | 44.1 kHz    | full      | 0.004708 | 0.00000081  | 0.007397 |
  | 44.1 kHz    | abrupt    | 0.004024 | 0.00012347  | 0.014630 |
  | 48 kHz      | idle      | 0.000914 | -0.00000043 | 0.002293 |

## Review

- Self-review covers the complete ticket diff, the unchanged event input
  contract, sub-sample timing, pulse continuity, block partitioning, filter and
  limiter order, finite/fault paths, mute behavior, bounded active state, and
  offline/Worklet independence.
- Self-review found that the initial 6000 rpm test could count energy from
  overlapping tails rather than individual triggers, and that accepted dense
  events had no explicit active-state bound. Trigger telemetry plus a 49/50
  negative check and a configurable default-256 active-pulse bound with a
  fault-to-silence regression correct both issues.
- Independent Terra high review found four actionable issues: attacker-sized
  event input was fully traversed before the active bound, the processing path
  allocated an object and grew map arrays per trigger, ordinary low-level tests
  did not activate the limiter, and this report still described an earlier
  pre-correction test run. The correction adds an O(1) per-block event bound,
  replaces active objects with preallocated fixed-capacity typed arrays, adds a
  dense-overlap limiter regression, and refreshes the evidence. It also adds a
  load amplitude/width regression and rejects a rounded-to-one DC coefficient.
- A bounded Terra medium `ticket-worker` implemented the DSP and offline tests.
  The orchestrator retained contracts, numerical review, integration, Git,
  reporting, and delivery ownership.
- The same independent reviewer rechecked the complete substantive correction,
  confirmed all four findings resolved, and found no new actionable correctness,
  state, timing, or bounded-work regression. No actionable findings remain.
