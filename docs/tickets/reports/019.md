## Acceptance evidence

- `tests/e2e/worklet.spec.ts`, `supports keyboard controls, explicit visibility
resume, and processor recovery`, uses keyboard input for preset and phase
  configuration, apply, start, throttle, mute, resume, and stop. It requires a
  hidden document to reach `suspended`, verifies that becoming visible does not
  resume audio, and requires an explicit keyboard Start action.
- The same product E2E case injects `processorerror`, requires the typed alert,
  and verifies a later keyboard Start creates and runs a replacement graph.
  `tests/audio/controller.test.ts`, `handles processor failure by detaching the
graph before recovery`, additionally requires the failed node to disconnect,
  its context to close, its analyser source to disappear, and a fresh context and
  node to be created.
- `tests/audio/controller.test.ts` covers fade-before-suspend, explicit-only
  resume, hide during pending Worklet load, external context suspension, and a
  stop racing the visibility fade. `tests/audio/lifecycle.test.ts` fixes the
  corresponding browser-independent state transition.
- `tests/e2e/worklet.spec.ts`, `deduplicates rapid starts and permits lifecycle
restart without graph duplication`, observes the development StrictMode
  mount/cleanup cycle and requires one graph for duplicate starts and exactly one
  new node for restart. `updates analyser canvases only for the live graph and
cleans up on restart` verifies that analyser reads stop and the analyser is
  disconnected on each stop. The visibility instrumentation requires one active
  listener after the StrictMode cleanup, and both the App visibility effect and
  visualization effect return listener/animation cleanup functions.
- `src/app/App.tsx` retains native labels for transport, ranges, numeric input,
  mute and configuration fields, supplies range value text, focuses the first
  invalid phase, and limits live announcements to status changes and submitted
  validation errors. `announces multiple invalid phases once and focuses the
first invalid field` requires two invalid controls to produce one alert and
  moves focus to the first invalid input.
- `tests/e2e/worklet.spec.ts`, `honors reduced motion without changing audio
playback`, starts the product graph to `running` while requiring no analyser
  canvases or reads and a non-live explanatory message. The reduced-motion value
  is consumed only by `EngineVisualizations`; controller and audio-thread timing
  are unchanged.
