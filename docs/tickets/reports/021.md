  long-lived hashed assets, non-cached HTML and stable Worklet entry, browser
  security headers, and a 404 for a missing asset.
- `make e2e` passed all 30 Chromium cases across the Vite and production Nginx
  projects. In particular,
  `loads an emitted JavaScript AudioWorklet and receives ready after a click`
  exercised the emitted Worklet under the production response headers.
- `docs/production-deployment-runbook.md` records the HTTPS secure-context
  requirement and localhost distinction, immutable image and release record,
  rollout/health verification, rollback, and the prohibition on baking secrets
  into the image.

  approval fields. Hosting and license remain unapproved, so no external write,
  deployment, DNS change, certificate request, registry push, or scan was
  performed.

## Review

- Self-review covered the complete `origin/main` diff, Nginx location matching
  and header inheritance, cache invalidation for the stable Worklet URL,
  cleanup of the temporary verification container, and the distinction between
  local HTTP evidence and future HTTPS/manual evidence.
- A bounded Terra medium `ticket-worker` prepared the deployment and decision
  documentation. Git, shared build configuration, Nginx integration, and final
  verification remained with the orchestrator.
- A fresh Terra high `ticket-reviewer` found two P2 gaps: the runbook did not
  spell out the implemented response policy, and the image probe checked only
  the presence of three policy headers. The runbook now maps paths to
  MIME/cache behavior and documents the security-header contract; the probe
  now checks the required CSP directives and exact Permissions/Referrer values.
  The reviewer rechecked both corrections and found them resolved with no new
  actionable regression.
