## Acceptance evidence

- `tests/e2e/worklet.spec.ts`, `runs the product audio controls without creating
audio before the user starts it`, exercises the emitted product UI in both
  Vite and Nginx: range and number inputs share the controller throttle value;
  pointer down opens it; pointer cancel, window blur, and Space keyup return it
  to zero; and Space in a number input is not captured. The same case checks
  the accessible labels and displayed values for throttle and dynamometer load.
- `tests/audio/controller.test.ts`, `sends throttle through its a-rate
AudioParam`, retains the canonical controller clamp to `[0, 1]`.
  `clamps dynamometer load in N m and sends it through its a-rate AudioParam`
  verifies the shared 40 N m boundary, initial graph value, and live update.
- `tests/audio/engine-audio-processor.test.ts`, `smooths a-rate dynamometer load
at dynamics boundaries`, checks the descriptor and compares
  unloaded, per-frame alternating, and scalar maximum-load trajectories through
  the production processor. Greater load produces lower RPM.
- `tests/engine/dynamics.test.ts`, `lowers steady RPM by applying dynamometer
T_load without changing throttle`, advances equal 0.65-throttle trajectories
  for eight seconds and verifies equal effective throttle but a load-induced RPM
  reduction greater than 100 RPM.

## Review

- Self-review covered the complete `origin/main` working diff: shared UI state,
  pointer/keyboard cancellation and focus behavior, controller clamping,
  AudioParam shape and units, fixed-step load application, realtime allocation,
  accessibility, tests, and documentation.
- The first delegated implementation released throttle on every global pointer
  up/cancel and could leave Space-held throttle active if focus moved into an
  input before keyup. Active pointer/keyboard refs now guard release, and E2E
  covers normal input focus, pointer cancel, focus loss, and post-focus keyup.
- The orchestrator centralized the duplicated AudioParam name/range in
  `src/audio/worklets/contracts.ts`, added actual per-frame a-rate trajectory
  evidence, added a bounded 50 ms load lag, and updated README/CONTRIBUTING
  behavior descriptions.
- A bounded Terra medium `ticket-worker` implemented the UI, controller,
  processor, and tests. The orchestrator retained shared contracts,
  integration, review, documentation, Git, and delivery ownership.
- A fresh Terra high `ticket-reviewer` found three implementation defects:
  pointer release outside the browser could leave throttle held without pointer
  capture; releasing one of simultaneous pointer/keyboard holds incorrectly
  released both; and load changed as a torque step without the planned
  smoothing. The corrections add pointer capture and lost-capture handling,
  source-specific hold state with both release orders covered in E2E, and a
  bounded 50 ms first-order effective-load state. Independent correction
  recheck confirmed all three findings resolved and found no new actionable
  defect. No actionable review finding remains.
