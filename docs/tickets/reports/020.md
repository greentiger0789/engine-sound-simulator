## Acceptance evidence

- The runbook's browser matrix requires Windows Chromium, Microsoft Edge, and
  Firefox rows for audible start, silent stop, stopped preset application on
  the next start, intentional invalid-phase error display, console errors, and
  browser-specific Worklet or feature differences. All three host rows remain
  `not-tested` pending execution on Windows.
- The runbook requires an application-owned `AudioContext` sample rate of
  48 kHz, the evenly spaced four-cylinder preset, exact start/end timestamps,
  ten continuous minutes, audible-dropout and processor-error checkpoints, and
  browser CPU/memory/profiler observations. The mandatory baseline run remains
  `not-tested` because this environment has no Windows browser or physical
  audio-output observation.
- The runbook measures input-to-audible response with a shared physical input
  marker and speaker recording for at least three unmute trials. It requires
  every uncorrected trial to be at most 50 ms, retains the raw timestamps and
  recording metadata, and records throttle-to-RPM response separately. This
  mandatory measurement remains `not-tested` because no physical recording was
  made.
- `tests/e2e/worklet.spec.ts` continues to provide native Chromium preflight
  coverage for successful Worklet start/stop, four-cylinder
  pending-configuration promotion, client-side invalid-phase validation, and
  both Vite and Nginx delivery paths. Separate injected-failure cases cover
  typed Web Audio error and recovery UI branches; they are not evidence that
  native failures occurred in Windows browsers. Neither automated path
  substitutes for a host row or listening measurement.

## Review

- Self-review covered the complete `origin/main..6e95420` diff for every Ticket
  20 recording field, actual application-context sampling, pass/fail semantics,
  production and development URLs, the 48 kHz gate, ten-minute checkpoints,
  separation of Bluetooth and mechanical RPM response, and the prohibition on
  converting headless success into host evidence.
- A bounded Terra medium `ticket-worker` prepared the runbook. The orchestrator
  corrected the audible-response method to use unmute rather than an
  intentionally smoothed throttle change, clarified the app-context breakpoint,
  and added exact production startup and resource-observation guidance.
- Independent Terra high review found that the initial wording could permit a
  failed mandatory check to coexist with `verified`, did not reconfirm the
  promoted active preset for the separate baseline run, underdefined physical
  response-waveform timestamps, treated a browser-reported zero latency like a
  missing property, allowed an observed Firefox incompatibility to be called
  untested, and blurred native and injected E2E failures. All six findings were
  corrected. The first recheck found a zero-threshold acoustic edge case and a
  remaining E2E evidence-classification error; both were corrected, and the
  final recheck reported no actionable findings.
